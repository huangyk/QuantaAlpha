# 战法接收标准流程（Warfare Intake SOP）

> 用途：**用户每给一个战法，我按本流程走完，而不是回测完就交差。**
> 定位：**流程编排**。细则见 `research_sop.md`（怎么回测才对）；归档见 `warfares_catalog.md`；生态见 `a_share_warfare_landscape.md`。
> 起因：2026-10-14 用户批评 ——「回测完成后需要去研究，不是回测完成就完成了」。

---

## 0. 核心原则

> **回测只回答"这个战法是否有效"（一关）。**
> **研究要回答"为什么有效 / 何时有效 / 能否改进 / 值不值得用"（还有五关）。**

过去的错误：把阶段 1 当成终点，交付一份"❌ 无 alpha"就完事。
本流程强制：**阶段 1 之后必须继续走 2–6，任何一关跳过都算未交付。**

---

## 1. 六阶段总览

| 阶段 | 回答的问题 | 关键产出 | 工具/依据 |
|:---|:---|:---|:---|
| **0 解析** | 这战法到底怎么算？ | 可计算表达式 + 数据依赖清单 + 可测性标注 | Qlib 表达式引擎 |
| **1 回测** | 行不行？ | ✅/⚠️/❌ 判定 + 完整证据链 | `research_sop.md` §1/§5 |
| **2 归因** ★ | **为什么？** | 风格/成本/执行/regime 四张归因表 + 一句话定性 | 本文 §3 |
| **3 边界** | **什么时候行？** | 分年 / 分池 / 分参数 矩阵 | 本文 §4 |
| **4 改进** | **能不能救？** | 过滤/执行/组合 三类改进方案（每个都回测验证） | 本文 §5 |
| **5 组合价值** | **值不值得用？** | 与现有策略相关性 + 边际贡献 + 容量 | 本文 §6 |
| **6 交付** | — | `docs/<战法名>_verdict.md` | 本文 §7 |

---

## 2. 阶段 0：解析（收到战法第一件事）

1. **精确化**：写成 Qlib 表达式（可计算、可复现），明确
   - 触发日（T 日收盘）、买点（**T+1 开盘**）、卖点（最早 T+2 起）、止损/止盈、最长持有
   - 禁止"盘中出现""盘中涨停"这类日线无法复现的描述
2. **数据依赖清单**：逐个零件标注能否测
   - ✅ 只用 OHLCV/amount → 可测
   - ❌ 依赖 `COST()` / `WINNER()` 筹码分布 → **本库无此数据**，如实告知用户，**不得用 akshare 替代**
3. **样本与区间**：有效可交易历史 = **2020–2026**（2011–2019 过稀）

**产出**：一张"零件 → 公式 → 可测性"表。

---

## 3. 阶段 1：回测（"行不行"）

按 `research_sop.md` 走完，**七道关卡全过才给 ✅**：

1. 信号-收益对齐（手算一天验证）
2. 三口径基准并列（等权 / 中位数 / 同 amount 十分位）
3. 分位单调性（D1−D10 与 RankIC 同号）
4. OOS walk-forward 方向不反转
5. 成本 0.5% 档仍为正（否则标注失效阈值）
6. 参数网格呈高原非尖峰
7. 低吸类带 ≤8% 止损对照

**产出**：✅/⚠️/❌ + 完整数据表（不是一句话结论）。

> ⚠ 前置硬检查（2026-10-14 新增）：**先查数据质量**——`bars_1d` 的
> `(asset_code, trade_date)` 唯一性、5m 的日根数、复权口径。数据脏则一切作废。

---

## 4. 阶段 2：归因（★ 过去最缺的一关）

回答"这个边到底是什么性质"。**四张表缺一不可**：

### 2.1 风格归因
- 超额按 **滞后 60 日 amount 十分位** 分档（禁用当日分档）
- 超额按 **SW1 申万一级行业** 分档
- 判据：**若正超额集中在极端规模档 → 判为"风格"而非 alpha**

### 2.2 成本归因
- 报 **毛 alpha**（0 成本）与 0.25%/0.5%/1% 四档
- 判据：**毛 alpha 为正、仅被成本吃光 → "成本问题"**（可救）；
  **毛 alpha 本身为负 → "信号死了"**（不可救）

### 2.3 执行归因
- 买入：T+1 开盘价 vs 全天 VWAP vs TWAP vs 限价单
- 判据：**能否靠执行把成本压到毛 alpha 之下**

### 2.4 Regime 归因
- 分年度 + 分市场状态（牛/熊/震荡，用全A 等权指数 SMA200 判定）
- 判据：**边是否只在特定环境下存在**

**产出**：**一句话定性** —— 这个边是「真 alpha / 风格 / 成本 / 择时 / 纯噪声」中的哪一种。

---

## 5. 阶段 3：边界（"什么时候行"）

| 维度 | 做法 |
|:---|:---|
| 时间 | 逐年 / 分 regime |
| 池子 | 大盘 / 中盘 / 小盘；不同行业 |
| 参数 | 关键参数扫描，确认高原还是尖峰 |
| 样本 | bootstrap CI（小样本必报） |

**产出**：条件矩阵 —— "在 X 条件下有效、在 Y 条件下失效"。

---

## 6. 阶段 4：改进（"能不能救"）

三条改进路线，**每条都必须回测验证**（不能只提方案）：

1. **降换手**：加过滤条件（信号质量、市场状态门控）
2. **降成本**：改执行方式（限价单、择时下单）
3. **组合**：与现有策略叠加

**判据**：改进后是否越过打平线（毛 alpha > 成本）。若都救不活 → 明确写"不可救"。

---

## 7. 阶段 5：组合价值（"值不值得用"）

- 与现有主力策略（**ETF 底盘**）的**相关性**
- 叠加后的 **夏普 / 回撤 / 年化** 边际变化
- **容量估算**：策略能承载多少资金（按 participation 上限）

**判据**：相关性低且边际夏普提升 → 值得纳入；否则单看收益再高也不加。

---

## 8. 阶段 6：交付

**一份 `docs/<战法名>_verdict.md`**，结构固定：

```
1. 一句话结论（状态 + 定性）
2. 信号定义（可计算表达式）
3. 数据与口径（区间、池子、成本、基准）
4. 回测结果（七关卡证据表）
5. 归因（四张表 + 定性）
6. 边界（条件矩阵）
7. 改进尝试与结果
8. 组合价值
9. 诚实边界（数据缺口、未验证区间、探索性标注）
10. 复现命令（脚本 + provider 路径）
```

同时更新 `warfares_catalog.md`（战法状态表）。

## 9. 反面清单（我犯过的错，逐条禁止）

| # | 禁止 | 后果 |
|:---|:---|:---|
| 1 | **回测完就交差**（只答"行不行"） | 用户要的是研究，不是排错 |
| 2 | 手写 pandas 回测框架 | 重复劳动 + 出 bug（已出过"重复行"事故） |

| 4 | 用"每日横截面复利"当基准 | 基准失真，超额虚高/虚低 |
| 5 | 报结论不报边界 | 无法判断可用性 |
| 6 | 用 akshare 替代 QMT 缺的数据 | 违反用户硬规则 |

## 10. 技术底座（2026-10-14 起统一）

- **数据**：Qlib 数据集 `D:/qqmt/qlib_data/cn_daily_clean`（2011-01-04~2026-10-13，5397 只）
  重建命令：`cd /d/qqmt/quant_datahub && python -m datahub dump-qlib --period 1d --out /d/qqmt/qlib_data/cn_daily_clean`
- **因子**：Qlib 表达式引擎（一行表达式，不手写 rolling）
- **回测**：`qlib.backtest` + 自定义 benchmark（三口径）与 cost model
  - ⚠ 需自写：① `TopkDropoutStrategy` 不支持止损/止盈；② 三口径基准
- **Windows 坑**：脚本必须 `if __name__ == "__main__":` + `QLIB_KERNELS=1`
