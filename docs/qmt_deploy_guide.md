# QMT 导入与运行指引（.rzrk 限制的解决方案）

> **一句话结论：`.rzrk` 我造不出来（迅投强加密），但你手动粘贴一次代码，QMT 自己就能生成。**
> 已验证：QMT 保存策略时会**自动加密**写入 `python/` 目录（你新建的 `新建策略文件1.py` 就是密文），
> 所以「直接把 .py 丢进 python 目录」QMT **不认**——这是我上次判断错的地方。

---

## 一、为什么只能手动粘贴（已核实的事实，不是推测）

| 事实 | 证据 |
|---|---|
| `.rzrk` 是强加密二进制 | `{QMT}/template/*.rzrk` 熵值 **7.94~7.97**（8.0=完全随机），无可用结构 |
| 策略文件也是加密的 | `python/飞龙.py` 解码后熵 **7.97**，真 AES 类加密，无法逆向生成 |
| QMT 只认自己加密的条目 | 你在 QMT 里建的 `新建策略文件1.py` 是**密文**；官方示例 `PY组合模型.py` 才是明文 |
| QMT 有解密能力 | 官方文档：导入 rzrk 后「**能看到源码**」→ 加密/解密都在 QMT 内部 |

**结论**：任何外部方式都无法生成合法的 QMT 策略文件。唯一路径是**在 QMT 里操作，让 QMT 自己加密并保存**。

## 三、★回测 vs 模拟：两者行为完全不同（必读）

策略日志里的 `account=` 为空、`capital=-1` 是**正常现象**，取决于你点的是哪个按钮：

| 你点的 | 模式 | `account` | `capital` | 策略行为 |
|---|---|---|---|---|
| **【回测】** | 历史回放 | 空（正常） | 你设的初始资金 | **正常出信号与订单** |
| **【模型交易】+模拟** | 实时仿真 | 空（除非已绑账号） | **−1** | **安全停下，不下单** |

### 为什么要这么设计
模拟/实盘模式下 `capital` 往往是 **−1**。若直接拿去算仓位会得到**负仓位**，
可能下出错单（这是危险的）。所以策略加了硬拦截：

```
[absmom] [STOP] 无有效资金(-1), 本次不调仓、不下单。
[absmom] [STOP] 常见原因: 你跑的是【模型交易】而不是【回测】。
```

**宁可不下单，也绝不下错单。**

### 你要做的
点 **【回测】**（不是【模型交易】），设置：
- 回测区间 **2019-01-01 ~ 2026-09-30**
- 初始资金 **80000**
- 周期 **日线**

### 模拟/实盘要下单时
在【模型交易】界面**先绑定资金账号**。绑了之后策略会自动改用账户真实资产
（`get_trade_detail_data` 查到总资产），日志不再出现 `[STOP]`。

已验证的四种组合：

| 场景 | 结果 |
|---|---|
| 回测 8万 / 无账号 | 11 单 ✅ |
| 模拟 capital=−1 / 无账号 | **0 单（安全停下）** ✅ |
| 模拟 capital=−1 / 已绑账号 | 11 单 ✅（改用账户资产） |
| 回测 8万 / 已绑账号 | 11 单 ✅ |

## 四、代码已在 QMT 真实环境核对过

`quantaalpha/strategy/absmom_qmt_model.py`（即 `docs/absmom_qmt_paste.txt` 的来源）：

- 按本机 `{QMT}/python/_PyContextInfo.py`（QMT API 引擎）**逐个核对**接口写就
- **只依赖 numpy**（QMT 自带），无 Python 3.7+ 语法（QMT 内置 3.6.8）
- GBK + CRLF 编码，语法编译通过

**API 要点（与 Ptrade 不同，容易踩）**：

| 用途 | 写法 | 说明 |
|---|---|---|
| 买入/卖出 | `passorder(23, 1101, account, code, 5, -1, vol, 备注, quickTrade, "absmom", C)` | **全局函数**，不在 ContextInfo 里 |
| 查持仓 | `get_trade_detail_data(account, "STOCK", "POSITION")` | 同为全局函数 |
| 查资金 | `get_trade_detail_data(account, "STOCK", "ACCOUNT")[0].m_dAvailable` | **单位是分，需 /100** |
| 取行情 | `ContextInfo.get_market_data_ex(["close"], POOL, period="1d", count=N)` | 官方推荐；`get_history_data` 是旧接口 |
| 截历史K线 | `if not ContextInfo.is_last_bar(): return` | **漏写会疯狂废单** |
| ETF 下单 | orderType 必须 `1101` | ETF 申赎只能用此参数 |
| 枚举 | 23=买入 24=卖出；5=最新价；quickTrade 0=K线结束 2=立即 | |

## 五、回测对数（这一步只能你做）

我没在真实 QMT 客户端跑过回测（沙箱起不了 QMT），所以**回测由你跑**。
设置：回测区间 **2019-01-01 ~ 2026-09-30**、初始资金 **80000**、周期 **日线**。

| 指标 | 期望值 |
|---|---|
| 年化收益 | 约 **+10%** |
| 最大回撤 | 约 **−9.4%** |
| 调仓次数 | 全年约 **12 次** |

### ⚠️ 回测前必须先补数据
QMT 本机 `datadir` 里 38 只 ETF 有 **13 只历史不足 200 日**：

```
159967:254行  159981:127  159985:157  161226:203  511380:77   512400:206  513080:31
513090:84     513100:256  513500:92   513730:189  518880:207  563300:239
```

只有 `159981`(2026-03上市)、`161226`(2025-12上市) 是**真次新**，
其余 11 只是 **QMT 侧历史数据下载不全** —— 须在 QMT【数据下载】补日线，否则这些标的不参与信号，回测结果会偏低。

策略内置诊断，会打印：
```
[absmom] [tip] history<200 skipped: 159967.SZ:254 513080.SH:31 ...
```
看到这行 = 确认哪些标的被跳过。

## 八、排障

| 现象 | 原因 / 处理 |
|---|---|
| 粘贴报 `SyntaxError: encoding problem` | 编辑器按 UTF-8 解析 → 首行改 `#coding:gbk` |
| `NameError: name 'passorder' is not defined` | 在 QMT 外运行了 → 须在 QMT 内运行 |
| 回测结果为空 / 全部不交易 | QMT 侧 ETF 日线没下载完 → 【数据下载】补 38 只 |
| 提示 `history<200 skipped` | 对应标的 QMT 数据不足 200 日 → 补数据或接受它被跳过 |
| `account` 为空 | 【模型交易】界面里没绑账号 |
| 报某 API 不存在 | QMT 版本较旧 → 把报错发我，我按该版本改 |
