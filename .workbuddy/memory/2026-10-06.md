## 5min 组合真实 P&L 打通（重大更正：旧结论"需 1min 数据集"是误判）

用户选定"建 1min 数据集跑真实 P&L"后，我**先查证再动手**，结论：**1min ETL 根本不需要**（且我们也没有 1min 源数据）。所谓"P&L 出不来需 1min"是误判——真实根因是 qlib 分钟回测里 3 处硬编码 `day` 频率假设，在只有 5min 日历的 cn_5m_full 上连续炸掉。**用现有 5min 数据即可出真实 P&L**。用户也确认"训练测试要吻合、大概率就这么多数据"，故不扩数据、不做 1min ETL。

### 3 个真实 bug（均已修，配 5min 组合 P&L）
1. **基准要 day 日历**：`Account.reset_report→PortfolioMetrics._cal_benchmark` 对字符串基准调 `get_higher_eq_freq_feature(freq="day")` → `can't find a freq ... resample to 1min`，整个 portfolio 块崩（P&L 全 N/A）。
   修（runner.py `_train_and_backtest`）：**传 pd.Series 基准**（股票池等权 step 收益），`_cal_benchmark` 对 Series 走 `isinstance(benchmark,pd.Series): return benchmark` 直接返回，跳过 day resample。
2. **exchange 报价默认 day**：`get_exchange(**exchange_kwargs)` 没传 freq → `Exchange.get_quote_from_qlib` 用 `freq=self.freq`=day 取报价 → `cn_5m_full does not contain data for day`。
   修：runner 传给 qlib_backtest 的 `exchange_kwargs` 里显式加 `"freq": self.freq`。
3. **5min 下因子复算被劫持 provider**：`_init_qlib` 实际用 env `QLIB_DATA_DIR`(=cn_real_full/day)，非 config 的 cn_5m_full；且 `CustomFactorCalculator` 在需要复算时又 `qlib.init` 回 cn_real_full，把全局状态覆盖 → GARKLINE_48/96 复算失败 + 后续全崩。
   修：config 加 `data.force_provider_uri: true`（runner 早有此开关）；并让 `custom_factor_calculator.get_qlib_stock_data` 同样尊重 `force_provider_uri`（此前它只认 env）。

### 关键坑：自建基准的 pct_change 维度
第一次修完 3 处，P&L 能算了但数值荒谬（年化 −19205%、回撤 −3123%、每步 excess 恒 −1.5）。dump `report_full.csv` 确诊：
- `return` 列**真实合理**（mean 0.0004/std 0.0033，账户 100M→146.5M）；策略本身没问题。
- `bench` 列全是 ~1.5 —— 自建基准算错：我写成 `groupby(level='datetime')['$close'].transform(pct_change)`，这是**同一时间戳内跨股票**比相邻价格（乱数）。应**按 instrument 沿时间**算 pct_change 再按 datetime 跨股票取均值。
  `excess = return − bench − cost ≈ 0.0004 − 1.5 − 0.0002 ≈ −1.5` = 假崩盘根因。
