## 【结案】复验器归一化层的 4 个真 bug（都曾让因子"从没被独立复验过"）

复跑 `oos_validate`（12 因子 / 跳过 3 / 复算失败 4）后逐条定位，全部修完并改成
「平衡括号扫描 + 按函数名分派」的单趟重写（原正则版只能吃**一层**嵌套括号）：

1. **正则实参模式 `_ARG` 吃不住多层嵌套** ——
   `ZSCORE(TS_ZSCORE(TS_STD($return,20) - TS_STD($return,60), 60) * TS_SKEW($return,20))`
   外层 `Zscore` 的实参是两级以上嵌套，匹配不上 → 外层没展开 → 剩 `Zscore` → 判"不可复算"跳过。
   **本轮最优因子 Vol_Skew_Divergence_2 一直没被独立复验过，根因在这。**
2. **通用 TS_*→驼峰的转换顺序反了** —— 原来在展开之后跑，`TS_ZSCORE` 先被改成 `Zscore`
   再去找展开规则，永远找不到。现在一趟扫描里先分派再输出，不再有顺序问题。
3. **`RANK(x)` 口径大错（最严重）** —— qlib 的 `Rank(feature, N)` 是**时序滚动**排名
   （`rolling(N).rank(pct=True)`），而平台 `function_lib.RANK` 是**日截面**排名
   （`df.groupby('datetime').rank(pct=True)`）。**两者语义完全不同**，池子里十几个因子
   用的都是裸 `RANK(...)` → 此前那些复验数全是错口径。
   改法：`RANK(x)` → 占位符 `__CSRANK__(x)`，qlib 只算内层，算完按日分组 `rank(pct=True)`
   后处理（_csrank_postprocess）。`TS_RANK(x,N)` 才是时序 → 直通 qlib `Rank(x,N)`。
4. **`TS_QUANTILE` 实参顺序不统一** —— 池子里 `TS_QUANTILE($volume,0.25,20)` 与
   `TS_QUANTILE($close,20,0.2)` 同时存在，而 qlib 是 `Quantile(feature, N, qscore)`。
   改法：第 2 个实参若是 (0,1) 概率值就交换。
   另补 `TS_DELTA(x,p) -> x - Ref(x,p)`（qlib 无 Delta）。
5. 三元 `? :` 改写成 `(c)*a + (1-c)*b`（qlib 没三元运算符），仅当 c 为布尔比较时与平台口径等价，
   结果标记为"近似"，不与正常因子混排。
6. 数字字面量必须用正则整块吃掉（`1e-8`），否则扫描会把 `1e-8` 拆成 `1 e - 8`。

## 归一化层连修 12 个 bug（复验器终于能对"从没被独立复算过"的因子说话）

`tools/oos_validate.py` 的归一化层前后修了 11 个真 bug，共同特点是**都会让因子静默失效**
（不抛异常，只是"跳过/为空/算错"），所以之前每轮 2 小时的挖掘都在错误口径上评估。
修完自测 `tools/_norm_selftest.py` 17/17，新增 `tools/_nan_probe.py` 小样本探针。

1. `_ARG` 正则只能吃一层嵌套 → 多层嵌套 ZSCORE 因子判"不可复算"。改平衡括号扫描。
2. **裸 `RANK(x)` 口径大错**：qlib `Rank(feature,N)` 是**时序滚动**排名，
   平台 `function_lib.RANK(df)`（`factors/coder/function_lib.py:34`）是**日截面**排名。
   池子里十几个因子用的是截面 → 之前所有复验数都是错口径。改 `__CSRANK__` 占位符 + 后处理。
3. `TS_QUANTILE` 实参顺序池内不统一（`(vol,0.25,20)` vs `(close,20,0.2)`）→ 按 qlib
   `Quantile(feature,N,q)` 在第 2 参是概率值时换位。
4. `_rewrite_and_or` 死循环（`_open_of` 从空格起步 + 漏删 `&&` 本身）→ 边界扫描 + `range(64)` 硬上限。
5. `_rewrite_ternary` 条件截错（`_find_left_start` 把 `<` 当起点）→ 改用配对括号定位。
6. 规则生成串里残留 `TS_MAX` 被 `OP_CONVERSIONS` 全局 replace 啃成 `TS_Max` → 实参递归归一。
7. `unsupported_operators` 把 `__CSRANK__` 当未注册算子 → 池里所有裸 RANK 因子被跳过。加排除集。
8. **`MAX/MIN` 语义**：平台 `MAX(x,y)` = `np.maximum` **逐元素**（`MAX(0,x)` 即 ReLU），
   qlib `Max(feature,n)` 是**滚动**取大且第二参必须是窗口期 int，直传会在常量实参上炸
   `'int' object has no attribute 'get_extended_window_size'`。
   统一改 `max(a,b)=(a+b+|a-b|)/2`。**权威口径在 `backtest/factor_calculator.py` 的 OPERATIONS_DOC。**
9. `&&` 的边界不能是比较符：`"A > 0.4 && B >= C"` 被截成 `0.4` 和 `B`。
   边界只认括号与逗号；左扫描停在 `(` 处顺带整组取进（三元改写仍传 stops 集合）。
10. **单参 `ZSCORE(x)` 是横截面标准化**（OPERATIONS_DOC 明写：
    "Z-score of each element in the cross-sectional dimension of A"），
    我按时序展开成 `Mean(x)` → qlib `Mean.__init__() missing 1 required positional argument: 'N'`。
    新增 `__CSZ__` 占位符 + `_csz_postprocess`（按日分组 `(x-mean)/std`）。
11. **`$return` 被驼峰化成 `$Return`**（最阴的一个）：`_rewrite_calls` 的字符白名单带着 `$`，
    `$return` 被拆成 `$` + `return`，`return` 走 `_ts_to_camel` 的 `capitalize()` → `Return`，
    qlib 没有 `$Return` 字段 → **整列 NaN 且不抛异常**，表现为 RankIC 为空。
    池子里恰好只有 4 条「只用 `$return`、不碰 `$close/$volume`」的因子中招（F0/F5/F12/F14），
    其余用 `$close` 的因子因为不在替换规则里反而侥幸没事。
    现在 `$` 后标识符整块原样吐出，再由 `OP_CONVERSIONS["$return"]` 展开成 `($close/Ref($close,1)-1)`。
12. **`_find_left_start` 的起点计算方法错了（漏传 `pos`）**：三元改写里模板串的起点被写成
    `len(s)-1`（从串尾往前扫），且函数体里再引用 `pos` 就报 `NameError`。
    恢复 `def _find_left_start(s, pos)` + `c = pos-1` 后，**`COUNT((A)&&(B),5)` 从
    `((Count((A)) * ((B))), 5)` 变成正确的 `Count(((A)) * ((B)), 5)`** —— 括号其实是**平衡**的，
    所以只测括号平衡的用例抓不到，必须断言「`Count(` 出现次数 == 1」且「正则能匹配到 `Count(..., 5)`」。
    这个 bug 让 F6/F8 两条因子（`KMAOQ_Gate_Cross` 家族）复算必崩
    `Count.__init__() missing 1 required positional argument: 'N'`。
