### 本轮踩到的坑（写进铁律）
1. **基准与策略的成本口径必须一致**：基准没扣成本、策略每月扣 11.6% → 所有方案虚假显示 −11% 超额。
2. **2020-05-05 是数据残缺日**（全市场只有 120 只更新，2020-06-01 有 3412 只）。
   建仓/回测必须加完整性检查 `len(ok) > 0.5 * len(codes)`，否则在残缺横截面里等权。
3. **基准池不能剔除涨停开盘**：涨停只是「买不进」，不等于「不能持有」。

4. **战法的上市时长口径**：Qlib 无真实上市日期字段，`build_universe` 提供
   `mode='backtest'`（数据长度近似）与 `mode='live'`（真实上市日字典）。

## 数据架构（用户问 miniqmt 收紧怎么办）
用户担忧：miniqmt 未来收紧 → 历史数据拿不到 → 以后只能在 QMT/Ptrade 使用。

**实测结论：研究/回测完全不受影响。**
- TimescaleDB `bars_1d` 实测 **12,316,652 行 / 2011-01-04~2026-09-30 / 5364 只**，
  年度分布 2011-2026 连续无缺口，source='qmt'。
- 字段含 `amount` / `turnover_rate` / `capital` / `float_shares` / `total_shares`
  → **比 qlib cn_real_full 的 8 个价量字段更全**，可直接支撑流动性/市值中性化。
- 架构：DB(底座) → ETL → qlib bin(离线研究) → 策略代码(与下单解耦) → QMT/Ptrade(仅实盘增量)。
- 唯一依赖券商的环节是「每日增量拉当天行情」，量极小；换平台只影响这层。
- 待做：① 代码格式映射（DB `600000.SH` ↔ qlib `SH600000`，且 DB 混有指数需按 asset_type 过滤）
  ② DB→qlib ETL（能把回测区间从 2020 扩到 2011）③ 每日增量脚本。
- 环境坑：`quantaalpha` **没有 psycopg**，要用 `envs/qmt312` 或 base conda；
  配置键是 `database` 不是 `dbname`；连不上用 `docker exec quant-timescaledb psql -U quant -d quant_data -c`。
- 文档：`docs/data_architecture.md`
## ★★★ 重大更正：volume 单位是「手」（2026-10-08 上午）

用户让我检查数据可用性 → 顺带查出这个贯穿全项目的量纲错误。

**判据**：`amount / (close × volume) ≈ 100`，日线/5min 都成立，2011~2026 稳定。
**影响**：成交额被低估 100 倍 → participation 高估 100 倍 → 冲击成本高估 10 倍。

| 项 | 错误值 | 正确值 |
|---|---|---|
| liquid500 单票日成交额中位 | 429 万 | **4.29 亿元** |
| 1000万/30只 participation | 7.76% | **0.08%** |
| 冲击（全天/单时段） | 9.5/30.1 bp | **1.0/3.0 bp** |
| 一次换手成本 | 29~70 bp | **约 12 bp** |
| 换手 0.2/日 成本 | 14.65%/年 | **6.00%/年** |
| 飞龙 0.734 换手成本 | 53.75%/年 | **22.02%/年** |
| 可承受换手(alpha 20%) | 0.056/日 | **0.248/日（每 4 天）** |
| 战法容量上限 | 1000 万 | **数亿都可**（1亿/30只 participation 仅 0.78%） |

**结论变化**
- 战法 net 年化 **+19.85% 不变**（建仓成本只占 18.5bp，现约 11bp）
- 容量约束基本消失 → 战法可上**数亿**
- 「短期反转+量能退潮」因子：成本 12.46%→4.34%/年，净超额 +0.06%→+8.94%(t=0.42)，
  但**分位组 D1(Top20) 日均超额 −6.10bp 就是跑输基准** → 仍无效，
  只是原因从「成本太高」变成「选股无效」，后者更根本

**顺带修复**
- **数据库索引损坏**：`idx_bars_1d_trade_date_asset` 零页（硬关机导致），
  已 `REINDEX` 修复，表数据完整（1231 万行）。
  以后查询报 `unexpected zero page` 就 REINDEX 该索引。
