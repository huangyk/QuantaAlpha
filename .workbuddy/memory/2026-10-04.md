## 【决定性发现】唯一真实的 Alpha 是「低风险异象」，而且被 LGB 的符号掩盖了

15 条 Top 因子独立 RankIC（平台自报清一色 0.0596~0.0637）：

| 因子 | 平台 | 独立复算 | train/valid/test |
|---|---|---|---|
| F2 Vol_Spike 动量+放量 | 0.0637 | **−0.0321** | −0.029 / −0.040 / −0.035 |
| F11 Tail_Risk 振幅×动量 | 0.0600 | **−0.0268** | −0.023 / −0.040 / −0.029 |
| F12 Quiet_Fear 低波+负偏 | 0.0596 | **+0.0238** | +0.021 / +0.033 / +0.024 |
| F4 Vol_Corr 量价相关 | 0.0635 | −0.0229 | 三段同号负 |
| F9 Tail_Risk 振幅×动量符号 | 0.0600 | −0.0222 | 三段同号负 |
| F14 Asym_Quiet 偏度×波动比 | 0.0596 | −0.0207 | 三段同号负 |
| F6/F7/F8（Count 类） | 0.0605 | +0.0038 / −0.0014 / −0.0014 | 几乎为零 |
| 其余（F0/F1/F3/F5/F7/F10/F13） | 0.0596~0.0637 | −0.0097 ~ +0.0174 | 噪声 |

**两条结论**：
1. **平台 0.06 没有任何单因子能复现** → 全靠 LightGBM 多因子合成，单因子输入是噪声。
2. **波动/振幅/尾部风险族在 A 股是稳定负向的** —— 6 条里 5 条 train/valid/test **三段同号**，
   幅度 −0.02~−0.032。这是**低风险异象（low-risk anomaly）+ 反转效应**，批次里唯一的真信号。
   唯一的例外 F12 靠内置 `-1 *` 把符号掰正了才变成 +0.024 → 说明平台写了负号但没被单独验证，
   LGB 把它当普通输入权重吸收，方向信息丢失。
   → **取负号后 RankIC 就是 +0.032 / +0.027 / +0.023，是目前最强的单因子族。**

方法论教训：**只看 RankIC 绝对值会漏掉整个信号族**。必须同时看**符号与分段一致性**，
否则一个"负 Alpha"会被当成噪声丢掉，或者反过来被 LGB 学成正贡献。

### 【重要 bug】跑非默认数据集时，`.env` 的 QLIB_DATA_DIR 会抢走你的配置

现象：命令行明明 `QLIB_DATA_DIR=D:/qqmt/qlib_data/cn_5m_full`，
qlib 初始化却是 `data_path={'__DEFAULT_FREQ': WindowsPath('C:/Users/lenovo/.qlib/qlib_data/cn_real_full')}`。

根因（两处叠加）：
1. `runner.py:_init_qlib` 优先级是 `QLIB_DATA_DIR env > QLIB_PROVIDER_URI > self.config['data']['provider_uri']`，
   **环境变量压过配置**；而 `.env` 里写死了 `QLIB_DATA_DIR=C:/Users/lenovo/.qlib/qlib_data/cn_real_full`
   （日频默认），env loader 会**强制覆盖命令行传入的同名变量**。→ 設命令行根本不管用。
2. `runner.py` 只认 **`data:` 段**的 provider_uri，而我按 `conf_baseline_5min.yaml` 的写法放在
   **`qlib_init:` 段** → 即使环境变量不存在也会 KeyError / 拿错。

修复（commit `2fd6f3b`，最小侵入，不动 .env 所以不影响日频任务）：
```python
cfg_data = self.config.get('data') or {}
if cfg_data.get('force_provider_uri') and cfg_data.get('provider_uri'):
    provider_uri = cfg_data['provider_uri']          # 数据集自己说了算
else:
    provider_uri = (os.environ.get('QLIB_DATA_DIR')
                    or os.environ.get('QLIB_PROVIDER_URI')
                    or cfg_data.get('provider_uri')
                    or (self.config.get('qlib_init') or {}).get('provider_uri'))  # 补兜底
```
5min conf 里相应加：
```yaml
data:
    provider_uri: "D:/qqmt/qlib_data/cn_5m_full"
    freq: 5min
    force_provider_uri: true
```
验证：显式 `os.environ['QLIB_DATA_DIR']=...cn_real_full`（模拟 .env 抢占）后仍能落到 cn_5m_full。
**以后要在 QuantaAlpha 里跑任何非默认数据集（5min / 别的 frequency / 别的池），必须加这个开关。**

### 【第 3 个坑】PortAnaRecord（组合回测）要 resample 到 **1min**，5min 数据集必崩

真因（日志里在指标之后紧接着）：

[ValueError: can't find a freq from Freq(5min) that can resample to 1min!]
  qlib/cli/run.py:157 run() -> ... backtest / strategy ...

## ⚠️ 5min 复验的统计功效问题（比任何单轮结果都重要，必读）

**现象**：52 因子三段里，valid(2026-06) 与 train(2026-01~05) 的 IC 符号一致率 = **0.50**
—— 恰好等于抛硬币。而 |valid|/|train| 的中位数是 1.12（不衰减），所以不是数据缺口，
也不是截面离散度问题（6 月前瞻收益截面 std 0.0456，反而是全年最高之一）。

**根因**：5min 相邻 bar 共享 47/48 根前瞻价格路径，**真正独立的样本单位是交易日，不是 5min bar**。
6 月只有 ~21 个交易日；日 IC 标准差约 0.1~0.2 → 段 IC 的标准误 ±0.02~0.04。
对 IC≈0.02 的信号，一个月段就是纯噪声。**三段里 valid 只有 1 个月 = 该段判据失效。**

**后果**：「三段同号」对小量级因子是碰运气（3 段独立抛硬币同号概率 25%；
实测 22/52=42% 高于 25% 约 2.8σ，说明池子整体确有信号，但单条因子过审≠显著）。

**修法（已加进 oos_validate）**：
- 新增 `to_daily_ic()`：5min 截面 IC 先按 `index.normalize()` 折成每日一个 IC；
- 新增 `ic_tstat()`：t = mean/(std/sqrt(n))，n = **交易日数**；
- 输出列：`n_days / t_all / n_train,valid,test / t_train,valid,test`；
- 新增 `significant` 列：`|t_all| >= 2` 才算这段 IC 不是噪声。
- **判读顺序改为：先三段同号，再 |t|>=2，最后才看量级。** 少了 t 这一步就是在掷硬币。

**教训**：n 用错单位（5min bar 数 vs 交易日数）会让标准误虚高好几倍，
这是「看起来很严谨、实际是噪声」的典型来源。任何 5min 统计必须先折到日。
